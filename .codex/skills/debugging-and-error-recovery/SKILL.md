# Debugging and Error Recovery

## FrontMatter

- 실행 조건: 오류, 테스트 실패, 빌드 실패, 실행 실패의 원인 분석과 복구
- 실행하지 않는 조건: 오류가 없는 일반 구현 작업

## Input Contract

- 오류 메시지와 로그
- 재현 명령과 재현 조건
- 현재 브랜치와 작업 트리
- 최근 변경 사항
- 관련 코드·테스트·환경 설정

## Steps

1. 실패한 명령과 현재 브랜치를 확인한다.
2. 실패를 재현하고 전체 오류 체인을 확보한다.
3. 오류를 환경, 설정, 요구사항, 구현, 테스트 문제로 분류한다.
4. 직접 원인과 근본 원인을 구분한다.
5. 가장 작은 범위의 복구 방안을 선택한다.
6. 수정 후 같은 재현 절차를 실행한다.
7. 관련 기존 테스트와 회귀 영향을 확인한다.

## Output Contract

- 재현 조건
- 직접 원인
- 근본 원인
- 적용한 복구 내용
- 재검증 결과
- 남은 위험과 사용자 결정 사항

## Verification Gate

- [ ] 실패를 재현했는가?
- [ ] 오류 메시지의 원인 위치를 확인했는가?
- [ ] 수정 전후의 결과를 비교했는가?
- [ ] 회귀 테스트를 실행했는가?
- [ ] 해결되지 않은 문제를 성공으로 보고하지 않았는가?

## Failure Policy

- 재현되지 않으면 재현 조건을 먼저 확보한다.
- 같은 수정과 재시도를 반복하지 않는다.
- 세 번의 동일한 실패 후에는 사용자에게 원인과 필요한 외부 조치를 보고한다.
- 데이터 손실이나 광범위한 변경이 필요한 복구는 실행 전에 확인한다.

## Exit Criteria

- 원인이 확인되고 복구 또는 중단 기준이 결정되었다.
- 복구했다면 재현 절차가 통과했다.
- 복구하지 못했다면 재현 조건과 차단 원인이 보고되었다.

## Anti-Rationalization

- 오류 로그의 일부만 보고 원인을 단정하지 않는다.
- 테스트 기대값을 바꾸어 실패를 숨기지 않는다.
- 환경 문제와 코드 문제를 근거 없이 동일시하지 않는다.
- 실패한 검증을 실행한 것으로 간주하지 않는다.
