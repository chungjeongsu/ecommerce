# Requirements Validation Workflow

## 입력

검증할 도메인 요구사항이나 기능을 자연어로 설명한다.

예시: `재고 예약의 불변식과 누락된 예외 흐름을 검증해줘.`

`/requirement {도메인} {검증 대상}` 형식은 Workflow를 직접 지정하는 축약 표현으로 사용할 수 있다.

## 목표

요구사항을 구현 가능한 수준으로 검증한다.

새로운 비즈니스 규칙을 임의로 확정하거나 기능을 구현하지 않는다.

## 실행 절차

### 1. 컨텍스트 수집
- `AGENTS.md`, `docs/boundary/boundary.md` 확인
- 관련 `docs/domain/*.md` 확인
- 관련 기존 코드, 테스트, 요구사항 탐색
- 명령어에 명시된 범위 중심으로 검토

### 2. 요구사항 분석
- 정상 흐름, 예외 흐름 식별
- 관련 객체와 책임 식별
- 내부/Root/외부 불변식 식별
- 상태 전이 및 생명주기 검토
- 다른 Aggregate와의 협력 관계 검토

### 3. 요구사항 검증
다음 항목을 검사한다.

- 누락된 실행 조건 및 예외 흐름
- 기존 규칙과의 모순
- 불변식의 책임과 적용 범위
- 상태 전이의 누락 또는 충돌
- 중복 요청 및 동시성에서 발생할 수 있는 규칙 위반
- 검증 가능한 테스트 시나리오의 존재 여부

### 4. 판단 및 승인
발견 사항을 다음과 같이 분류한다.

- 확정: 기존 문서에서 근거를 확인한 규칙
- 누락: 필요한 규칙이 정의되지 않은 경우
- 충돌: 기존 규칙과 모순되는 경우
- 미확정: 여러 비즈니스 선택이 가능한 경우

새 규칙의 확정 또는 기존 규칙 변경은 사용자 승인을 요청한다.

사용자 승인이 필요한 핵심 사항이 있다면 관련 근거, 선택지, 영향을 설명하고 해당 판단을 보류한다.

### 5. 문서 반영
- 승인된 변경은 관련 도메인 문서에 반영한다.
- Aggregate 간 관계와 협력 불변식의 변경은 관련 도메인 문서에 반영한다.
- 미승인 사항은 미확정 상태로 기록한다.
- 의미가 동일한 규칙을 여러 문서에 불필요하게 중복하지 않는다.

## 완료 결과

다음 형식으로 보고한다.

1. 검증한 요구사항
2. 확인된 규칙 및 불변식
3. 누락·충돌·미확정 사항
4. 권장 테스트 시나리오
5. 문서 변경 내역

프로덕션 코드는 변경하지 않는다.
