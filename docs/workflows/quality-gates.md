# Workflow 품질 게이트

## 목적

문서·구현·테스트 사이에서 승인된 도메인 규칙이 누락되지 않도록 방지한다.

## 필수 요구사항 추적표

구현, 디버깅, 리팩터링, 요구사항 검증 작업은 코드 변경 전에 다음 추적표를 작성한다.

| 요구사항 | 대상 객체 또는 행위 | 상태·생명주기 | 테스트 시나리오 | 구현 위치 | 상태 |
| --- | --- | --- | --- | --- | --- |
| 도메인 규칙 | Entity, Aggregate, Usecase | 전이 및 종료 상태 | 정상·예외·경계 | 코드 위치 | 완료·보류·결정 필요 |

추적표에는 다음 항목을 포함한다.

- Entity와 Value Object의 불변식
- Aggregate 불변식
- Application 및 Aggregate 간 협력 규칙
- 상태 전이와 종료 상태
- 생성·수정·삭제·복구·이력 생명주기
- 영속화와 마이그레이션 요구사항
- 권한·소유권·중복·멱등성·동시성 규칙

## TDD 루프

각 규칙마다 다음 순서를 반복한다.

1. 규칙을 표현하는 테스트를 작성한다.
2. 테스트를 실행해 예상한 실패를 확인한다.
3. 통과에 필요한 최소 구현을 작성한다.
4. 대상 테스트와 관련 회귀 테스트를 실행한다.
5. 기존 프로젝트 규칙에 맞춰 리팩터링한다.

## 완료 게이트

다음 조건을 모두 충족하기 전에는 작업을 완료로 보고하지 않는다.

- 기준 문서의 모든 규칙이 추적표에 등록되어 있다.
- 승인된 모든 규칙에 테스트가 있거나, 아직 테스트할 수 없는 명시적인 사유가 있다.
- 정상·예외·경계·중복·상태 전이 경로를 검토했다.
- Aggregate 경계, 객체 책임, 생명주기를 검토했다.
- 관련 테스트와 전체 테스트를 실행했다.
- 미확정 요구사항, 보류된 의존성, 위험 요소를 보고한다.
- 가장 가까운 기존 구현과 코드 스타일을 비교했다.
- 문서의 언어·용어·형식이 프로젝트 문체와 일치한다.

## 자연어 작업 프롬프트

작업을 시작하기 전에 다음 형식으로 요청을 정리한다.

```text
요청 목적: 구현 / 디버깅 / 리팩터링 / 리뷰 / 요구사항 검증 / 문서 동기화
Workflow:
대상 도메인 및 계층:
작업 범위:
기준 문서:
추출한 규칙:
상태 및 생명주기:
Aggregate 간 의존성:
규칙별 테스트 매핑:
범위 제외 또는 미확정 항목:
완료 검증 항목:
```

## 최종 보고 프롬프트

완료 보고에는 다음 항목을 포함한다.

```text
변경 사항:
추가·수정한 테스트:
실행한 검증 명령과 결과:
문서·코드·테스트 대조 결과:
보류 또는 미확정 항목:
Git 상태 및 commit/push 상태:
```
