# Code Review Workflow

## 입력

검토할 코드 범위와 검토 관점을 자연어로 요청한다.

예시: `주문 취소와 재고 예약 해제 로직을 리뷰해줘.`

`/review {도메인 또는 변경 범위} {검토 관점}` 형식은 Workflow를 직접 지정하는 축약 표현으로 사용할 수 있다.

## 목표

실제 코드에서 발생할 수 있는 결함을 근거 중심으로 발견한다.

코드를 수정하는 것이 아니라 문제를 식별하고 검증하는 데 집중한다.

## 실행 절차

### 1. 리뷰 범위 결정
- 관련 정책과 도메인 문서 확인
- 변경된 코드와 기존 코드의 호출 경로 확인
- 관련 테스트 및 아키텍처 확인
- 명령어에 지정된 변경 범위를 우선 검토

### 2. 요구사항 검증
- 누락된 정상·예외 흐름
- 도메인 불변식 위반
- 잘못된 상태 전이
- 권한 및 소유권 검증 누락
- 요구사항과 구현의 불일치

### 3. 기술적 검증
- 트랜잭션 경계 문제
- 동시성 및 Race Condition
- 멱등성 및 중복 처리
- 예외 처리와 실패 복구
- 데이터 정합성
- 성능 및 리소스 관련 명백한 위험

### 4. 테스트 검증
- 주요 규칙에 대응하는 테스트 존재 여부
- 테스트가 실제 요구사항을 검증하는지 확인
- Mock에 의해 실제 결함이 가려지는지 확인
- 누락된 경계 조건과 통합 테스트 식별

### 5. 결과 분류
발견 사항을 다음 수준으로 분류한다.

- Critical: 데이터 손실, 중복 결제 등 치명적 결함
- High: 주요 불변식 위반 또는 기능 오류
- Medium: 특정 조건에서 발생하는 결함
- Low: 경미한 개선 사항

문제마다 다음 내용을 제공한다.

- 파일 및 코드 위치
- 문제 발생 조건
- 예상되는 영향
- 수정 방향
- 검증할 테스트 시나리오

근거가 불충분한 내용은 확정된 결함으로 표현하지 않는다.

## 완료 결과

1. 심각도순 발견 사항
2. 근거와 재현 조건
3. 권장 수정 방향
4. 누락된 테스트
5. 문서 불일치 및 미확정 사항

기본적으로 코드를 수정하지 않는다.
