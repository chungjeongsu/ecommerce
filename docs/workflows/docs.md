# Documentation Synchronization Workflow

## 입력

코드·테스트·문서 사이의 불일치를 확인하거나 문서를 갱신할 대상을 자연어로 설명한다.

예시: `Payment의 UNKNOWN 복구 규칙을 코드와 문서에 맞게 동기화해줘.`

`/docs {도메인 또는 범위} {변경 대상}` 형식은 Workflow를 직접 지정하는 축약 표현으로 사용할 수 있다.

## 목표

코드·테스트·문서 사이의 불일치를 탐지하고 승인된 변경을 관련 문서에 반영한다.

코드가 문서와 다르다는 이유만으로 코드를 정답으로 간주하지 않는다.

## 실행 절차

### 1. 변경 사항 수집
- 관련 도메인·아키텍처 문서 확인
- 대상 코드와 테스트 탐색
- 관련 변경 사항 확인
- 새로운 행위, 규칙, 상태 전이, 관계, 책임 식별

### 2. 문서 정합성 검증
다음 항목을 확인한다.

- 코드에 존재하지만 문서에 없는 규칙
- 문서에 존재하지만 구현되지 않은 규칙
- 도메인 객체 책임 변경
- Aggregate 간 관계와 협력 변경
- 상태 전이 및 생명주기 변경
- 아키텍처 결정과 실제 구현의 불일치

### 3. 변경 사항 분류

**A. 승인된 규칙의 누락**
- 기존 근거를 확인한다.
- 의미를 변경하지 않는 범위에서 문서를 보완한다.

**B. 새로운 비즈니스 규칙**
- 사용자에게 발견 내용과 영향을 보고한다.
- 승인 전에는 확정 규칙으로 반영하지 않는다.

**C. 기존 규칙과 충돌**
- 충돌하는 문서와 코드 위치를 제시한다.
- 사용자 판단 전까지 어느 쪽도 임의로 정답 처리하지 않는다.

**D. 기술적 설계 변경**
- 기존 아키텍처 정책을 확인한다.
- 승인 정책에 따라 관련 문서에 반영한다.

### 4. 문서 갱신
- 객체·행위·불변식: 해당 `docs/domain/*.md`
- Aggregate 간 관계·협력: 관련 `docs/domain/*.md`
- 기술적 설계 결정: `docs/architecture/`
- 테스트 전략 변경: `docs/testing/`
- 작업 절차 변경: `docs/workflows/`

같은 규칙을 불필요하게 여러 곳에 복사하지 않는다.

### 5. 재검증
- 변경한 문서 간 모순이 없는지 확인
- 미승인 규칙이 확정된 것처럼 기록되지 않았는지 확인
- 코드와 테스트가 승인된 요구사항에 부합하는지 확인

## 완료 결과

1. 탐지한 불일치
2. 갱신한 문서와 변경 내용
3. 사용자 승인이 필요한 사항
4. 남은 불일치

본 Workflow는 프로덕션 코드를 수정하지 않는다.
