# Debugging Workflow

## 입력

오류 현상이나 예상과 다른 동작을 자연어로 설명한다.

예시: `동시에 재고를 예약하면 초과 판매가 발생하는 원인을 찾아줘.`

`/debug {도메인 또는 시스템} {오류 현상}` 형식은 Workflow를 직접 지정하는 축약 표현으로 사용할 수 있다.

## 목표

추측이 아닌 재현 가능한 근거를 바탕으로 결함 원인을 분석하고 수정한다.

## 실행 절차

### 1. 현상 파악
- 관련 정책과 도메인 문서 확인
- 오류 메시지, 로그, 테스트 실패 내용 수집
- 관련 코드와 실행 경로 확인
- 기대 동작과 실제 동작 비교

### 2. 가설 수립
- 가능한 원인 후보 식별
- 각 가설의 근거와 확인 방법 정리
- 가능성이 높은 가설부터 검증

확인되지 않은 가설을 원인으로 확정하지 않는다.

### 3. 재현
- 가능한 최소 조건으로 문제 재현
- 재현 가능한 회귀 테스트 작성
- 테스트가 실제 결함 때문에 실패하는지 확인

### 4. 원인 분석
- 실패한 코드 경로 분석
- 불변식 및 상태 전이 검토
- 트랜잭션, 동시성, 외부 의존성 문제 확인
- 현상과 근본 원인 구분

### 5. 수정
- 확인된 원인을 해결하는 최소 변경 적용
- 새로운 비즈니스 판단이 필요하면 사용자 승인 요청
- 수정 후 회귀 테스트 실행
- 관련 기존 테스트 재실행

### 6. 재발 방지
- 동일 유형의 결함이 발생할 수 있는 위치 확인
- 필요한 테스트 보완
- 새로 발견한 규칙과 설계 결정을 관련 문서에 반영
- 추가 모니터링이나 구조 개선이 필요하면 후속 작업으로 분리

## 완료 결과

1. 오류 현상 및 재현 여부
2. 확인된 원인과 근거
3. 수정 내용
4. 회귀 테스트 및 검증 결과
5. 재발 방지 조치
6. 해결되지 않은 사항

재현 또는 원인 확인에 실패한 경우 해결했다고 보고하지 않는다.
