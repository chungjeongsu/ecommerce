## Boundary

### Always

- 변경 내용의 책임에 따라 `.agents/domain/`, `.agents/architecture/`, `.agents/testing/`에서 대상을 선택한다.
- 확정된 결정과 검증된 동작만 문서에 반영한다.
- 기존 문서의 구조와 용어를 유지하며 필요한 범위만 수정한다.
- 관련 문서 사이의 링크와 규칙 일관성을 확인한다.

### Ask First

- 어느 문서가 규칙의 소유자인지 판단할 수 없는 경우
- 기존 문서와 전달받은 변경 내용이 충돌하는 경우
- 새로운 도메인 규칙을 추가하거나 기존 규칙의 의미를 변경해야 하는 경우
- 문서 삭제, 대규모 재구성 또는 여러 규칙의 통합이 필요한 경우

### Never

- 코드의 현재 동작만 보고 새로운 도메인 규칙을 추론해 확정하지 않는다.
- 결함이나 임시 구현에 맞추기 위해 기준 문서를 왜곡하지 않는다.
- 요청과 무관한 문체 통일이나 문서 재구성을 함께 수행하지 않는다.
- 이 Skill에서 코드나 테스트를 수정하지 않는다.

## Input Contract

- 문서에 반영할 확정된 변경 내용과 근거
- 사용자 결정 및 요구사항 분석 결과
- 구현이 포함된 경우 변경 행위와 검증 결과
- 문서화 대상 범위 또는 이를 식별할 수 있는 정보

입력 형식은 제한하지 않지만 확정된 내용과 제안·미결정 내용을 구분할 수 있어야 한다.

## Responsibilities

- 변경 내용의 성격과 소유 문서를 식별한다.
- 관련 문서에서 기존 규칙과 중복, 충돌, 누락 여부를 확인한다.
- 확정된 변경을 최소한의 범위로 반영한다.
- 용어, 링크, 경로 및 문서 간 규칙의 일관성을 검토한다.
- 반영 결과와 남은 미결정 사항을 독립적으로 전달한다.

구체적인 편집 순서는 문서 의존성과 변경 범위에 맞게 결정한다.

## Output Contract

문서 동기화 결과를 독립적으로 검토할 수 있도록 아래 정보를 전달한다.

- 반영한 규칙과 변경 이유
- 변경한 문서와 각 문서의 역할
- 근거가 된 사용자 결정, 분석 또는 구현 결과
- 문서 간 일관성 검토 결과
- 반영하지 않은 제안과 남은 미결정 사항
- 동기화 완료 여부와 후속 작업에 필요한 조건

## Verification Gate

- [ ] 모든 변경이 확정된 근거를 가지는가?
- [ ] 변경 내용을 올바른 소유 문서에 반영했는가?
- [ ] 기존 규칙과 중복되거나 충돌하지 않는가?
- [ ] 관련 링크, 경로, 용어가 일관되는가?
- [ ] 코드나 테스트를 변경하지 않았는가?

하나라도 충족하지 못하면 동기화 완료로 전달하지 않는다.

## Failure Policy

- 확정 근거가 없으면 문서를 변경하지 않고 필요한 결정을 보고한다.
- 기존 문서와 충돌하면 충돌 내용을 전달하고 대기한다.
- 관련 문서를 읽거나 수정할 수 없으면 원인과 미완료 범위를 알린다.
- 일부만 반영된 경우 완료로 표시하지 않고 복구 가능한 상태를 유지한다.

## Exit Criteria

- 완료: 확정된 변경을 관련 문서에 반영하고 검증한 Output을 전달했다.
- 대기: 문서 소유권, 규칙 충돌 또는 사용자 결정이 필요하다.
- 실패: 필요한 문서 변경이나 검증을 완료할 수 없다.
- 취소: 사용자가 문서 동기화를 취소했다.
