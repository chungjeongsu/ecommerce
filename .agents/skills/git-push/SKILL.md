# Git Push

## Boundary

### Always

- 현재 저장소와 브랜치를 확인한다.
- 대상 원격과 대상 브랜치를 확인한다.
- 실제 merge-base부터 현재 HEAD까지의 전체 커밋과 diff를 확인한다.
- 작업 트리와 로컬·원격 커밋 차이를 확인한다.
- push 전 변경 범위와 검증 결과를 보고한다.
- 승인된 대상에만 push한다.
- push 후 원격 반영 상태를 다시 확인한다.

### Ask First

- push 승인이 현재 요청에 포함되지 않은 경우 승인받는다.
- 보호 브랜치에 push해야 하는 경우 확인한다.
- force push, amend, rebase 또는 이력 변경이 필요한 경우 확인한다.
- 기준 브랜치나 대상 원격이 불명확한 경우 확인한다.

### Never

- 전체 변경과 검증 상태를 확인하지 않고 push하지 않는다.
- 승인되지 않은 원격 브랜치에 push하지 않는다.
- 강제 push를 승인 없이 수행하지 않는다.
- 비밀 정보, 산출물과 범위 밖 변경을 push하지 않는다.
- 인증 거부, 충돌과 검증 실패를 성공으로 보고하지 않는다.

## Input Contract

- push할 현재 브랜치와 대상 원격 브랜치
- 기준 브랜치와 merge-base
- push 승인 상태
- 테스트·빌드·정적 분석·리뷰 결과
- 사용자 확인이 필요한 미해결 사항

대상, 승인 또는 필수 검증 상태가 불명확하면 push하지 않고 확인한다.

## Responsibilities

- 기준 브랜치부터 현재 HEAD까지의 전체 커밋과 diff를 확인한다.
- 작업 트리에 커밋되지 않은 변경이 없는지 확인한다.
- 모든 요청 변경이 커밋되었는지 확인한다.
- 비밀 정보, 산출물과 범위 밖 변경을 확인한다.
- 테스트, 빌드, 정적 분석과 리뷰 결과를 확인한다.
- 기준 브랜치, 대상 브랜치, 전체 커밋과 변경 파일을 보고한다.
- 승인된 대상에 push한다.
- push 후 로컬 HEAD와 원격 HEAD를 대조한다.

## Output Contract

- 기준 브랜치와 대상 브랜치
- 전체 커밋과 변경 파일
- 변경 사항의 구체적인 내용 {변경 제목}: {변경 상세 설명}
- 작업 트리와 커밋 반영 상태
- 테스트·빌드·정적 분석·리뷰 결과
- 미해결 사항

## Verification Gate

- [ ] 현재 브랜치와 대상 원격 브랜치를 확인했는가?
- [ ] 실제 merge-base부터 전체 커밋과 diff를 확인했는가?
- [ ] 작업 트리가 깨끗한가?
- [ ] 요청한 변경이 모두 커밋되었는가?
- [ ] 필수 테스트와 검증 결과를 확인했는가?
- [ ] 비밀 정보와 범위 밖 변경이 없는가?
- [ ] push 승인이 확인되었는가?
- [ ] push 후 로컬 HEAD와 원격 HEAD를 대조했는가?

하나라도 확인하지 못하면 push를 완료로 보고하지 않는다.

## Failure Policy

- 전체 변경을 확인하지 못하면 push하지 않는다.
- 작업 트리에 미커밋 변경이 있으면 push하지 않는다.
- 필수 검증이 누락되거나 실패하면 승인 전까지 대기한다.
- 승인이 없으면 보고만 전달하고 push하지 않는다.
- 인증 거부나 충돌이 발생하면 재시도하지 않고 원인과 상태를 보고한다.
- 원격 반영을 확인하지 못하면 성공으로 보고하지 않는다.

## Exit Criteria

- 완료: 승인된 대상에 push하고 원격 반영을 검증했다.
- 대기: 승인, 추가 검증 또는 사용자 결정이 필요하다.
- 실패: push 또는 필수 검증을 완료할 수 없다.
- 취소: 사용자가 push를 취소했다.
