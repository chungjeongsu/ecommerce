# Skill Create

프로젝트의 `.agents/skills/` 아래에 Codex Skill을 생성하거나 수정한다. Skill은 특정 작업의 판단 기준과 실행 절차를 제공해야 하며, 일반적인 상식이나 다른 Skill의 책임을 중복해서 담지 않는다.

## Boundary

### Always

- 사용자의 목적과 대상 Skill을 확인하고 생성과 수정을 구분한다.
- `.agents/skills/` 후보의 frontmatter를 먼저 읽고 관련 Skill의 본문만 읽는다.
- 반드시 Skill 디렉토리 경로와 자동 발견 규칙은 [references/skill-structure.md](references/skill-structure.md)를 읽는다.
- 반드시 Skill 구성 요소와 작성 원칙은 [references/design-principles.md](references/design-principles.md)를 읽는다.
- 작업에 필요한 문서 목록을 작업 전에 확정한다.
- 필수 문서는 본문을 끝까지 읽고 읽은 경로를 기록한다.
- 읽지 못했거나 일부만 읽은 필수 문서가 있으면 생성을 진행하지 않는다.
- 필수 지침을 실행 가능한 규칙과 검증 항목으로 변환한다.
- 각 필수 지침이 결과 Skill의 한 곳 이상에 반영되었는지 추적한다.
- 반영되지 않은 필수 지침이 있으면 완료로 보고하지 않는다.
- 컨텍스트가 압축되거나 작업이 재개되면 문서 목록과 핵심 규칙을 다시 확인한다.
- 확인되지 않은 내용을 추측으로 보완하지 않는다.

### Ask First

- Skill의 책임 범위가 기존 Skill과 충돌하는 경우
- 사용자가 지정한 경로가 자동 발견 경로인지 불명확한 경우
- 권한, 외부 변경 또는 파괴적 작업 범위를 새로 결정해야 하는 경우
- 기존 Skill의 규칙을 삭제하거나 의미를 바꿔야 하는 경우
- 자동 발견과 명시적 호출 방식이 불분명한 경우
- 해당 스킬의 구체적인 요구사항들이 Skill의 설계 원칙과 비교 시 부족한 경우

### Never

- 사용자의 요청 없이 기존 Skill을 삭제하거나 다른 Skill로 통합하지 않는다.
- 관련 없는 Skill, Workflow, 도메인 문서를 함께 수정하지 않는다.
- 일반적인 코딩 지식이나 긴 사용 설명서를 Skill 본문에 복사하지 않는다.
- 실제 검증하지 않은 Skill을 완성된 것으로 보고하지 않는다.
- Skill 파일에 비밀 정보, 개인 경로, 자격 증명 또는 환경별 임시 값을 넣지 않는다.

## Input Contract

- 생성하거나 수정할 Skill의 목적과 작업 범위
- Skill을 사용할 사용자 요청의 유형
- 필요한 실행 권한과 외부 변경 범위
- 기존 Skill과의 중복·충돌 여부
- 사용자 결정이 필요한 미확정 사항

입력에 목적, 범위 또는 권한이 없으면 작업을 시작하지 않고 확인한다.

## Responsibilities

- 필요한 문서와 reference의 목록을 작성한다.
- 목록의 필수 문서를 읽고 읽은 경로와 핵심 규칙을 기록한다.
- 원문 지침을 필수 규칙과 선택 규칙으로 분류한다.
- 각 필수 규칙을 Boundary, Contract, Responsibilities, Verification 또는 Failure Policy에 연결한다.
- 연결되지 않은 필수 규칙을 식별하고 작업을 중단한다.
- `SKILL.md`와 supporting resource를 작성하거나 수정한다.
- 원문 지침과 결과 파일을 다시 대조한다.
- 각 필수 규칙에 대한 관찰 가능한 검증 결과를 기록한다.

## Output Contract

- 생성하거나 수정한 Skill 경로
- Skill의 이름과 책임
- 추가·변경한 supporting resource
- 읽은 필수 문서와 reference 경로
- 적용한 필수 규칙과 결과 파일의 연결
- 실행한 검증과 결과
- 실행하지 못한 검증과 사유
- 사용자 결정이 필요한 미해결 사항

## Verification Gate

- [ ] `SKILL.md`가 올바른 Skill 디렉터리에 있는가?
- [ ] YAML frontmatter의 `name`, `description`이 유효한가?
- [ ] 이름이 디렉터리명과 일치하고 허용된 형식인가?
- [ ] 책임 범위가 명확한가?
- [ ] Frontmatter만으로 적용 Skill을 선택할 수 있는가?
- [ ] 필요한 계약이 다음 작업에 필요한 정보를 보존하는가?
- [ ] 필요한 책임과 권한이 정의되어 있는가?
- [ ] 필수 문서 목록을 작성했는가?
- [ ] 필수 문서의 본문을 끝까지 읽었는가?
- [ ] 읽은 문서와 읽지 못한 문서를 구분했는가?
- [ ] 필수 규칙을 실행 가능한 규칙으로 변환했는가?
- [ ] 모든 필수 규칙이 결과 파일에 연결되어 있는가?
- [ ] 모든 필수 규칙에 관찰 가능한 검증 항목이 있는가?
- [ ] 작성 후 원문 지침과 결과 파일을 다시 대조했는가?
- [ ] 실패 처리와 종료 상태가 정의되어 있는가?
- [ ] supporting resource가 필요하며 본문에서 연결되는가?
- [ ] 미완성 placeholder, 비밀 정보, 관련 없는 내용이 없는가?
- [ ] 생성·수정 결과와 미검증 항목을 정확히 보고했는가?

검증 항목을 충족하지 못하면 Skill 생성을 완료로 처리하지 않는다.

## Failure Policy

- 책임 충돌이 발견되면 사용자 결정 전까지 대기한다.
- 필요한 입력이 없으면 추가 정보를 요청한다.
- 필수 문서를 읽지 못하면 작업을 중단하고 누락된 경로를 보고한다.
- 필수 규칙을 결과 파일에 연결하지 못하면 작업을 중단하고 미반영 규칙을 보고한다.
- 지침의 의미가 모호하면 임의로 해석하지 않고 사용자에게 확인한다.
- 원문과 결과의 대조가 불가능하면 완료로 보고하지 않는다.
- 파괴적 변경이나 권한 확대가 필요하면 실행하지 않는다.
- 검증 실패 시 실패 원인과 미검증 범위를 보고한다.
- reference가 없거나 읽을 수 없으면 해당 규칙을 적용하지 않고 대기한다.

## Exit Criteria

- 완료: 필수 문서를 읽고 모든 필수 규칙을 반영·검증한 뒤 결과를 전달했다.
- 대기: 사용자 결정, 추가 입력 또는 권한이 필요하다.
- 실패: 문서 로딩, 지침 반영, 생성·수정 또는 필수 검증을 완료할 수 없다.
- 취소: 사용자가 작업을 취소했다.
