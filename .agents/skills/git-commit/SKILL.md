# Git Commit

## Boundary

### Always

- 현재 저장소와 브랜치를 확인한다.
- 작업 트리와 전체 diff를 확인한다.
- 커밋 대상과 대상이 아닌 변경을 구분한다.
- staged diff를 커밋 직전에 다시 확인한다.
- 커밋 후 커밋 내용과 남은 변경을 다시 확인한다.

### Ask First

- 커밋 범위가 요청과 일치하지 않는 경우 확인한다.
- 서로 다른 목적의 변경을 안전하게 분리할 수 없는 경우 확인한다.
- 파일 하나에 독립적인 변경이 섞여 분리가 필요한 경우 확인한다.
- 검증되지 않은 변경을 커밋해야 하는 경우 확인한다.

### Never

- 전체 변경을 확인하지 않고 커밋하지 않는다.
- 요청 범위 밖의 파일을 사용자 확인 없이 stage하지 않는다.
- 비밀 정보나 불필요한 산출물을 커밋하지 않는다.
- 검증 실패를 성공으로 보고하지 않는다.
- 사용자 승인 없이 amend, rebase, reset 또는 강제 변경을 수행하지 않는다.

## Input Contract

- 커밋할 사용자 요청과 변경 범위
- 적용할 커밋 메시지 규칙
- 이전 단계의 구현·검증 결과
- 사용자 확인이 필요한 미해결 사항

커밋 범위나 필수 검증 상태가 불명확하면 커밋하지 않고 확인한다.

## Responsibilities

- 저장소, 브랜치, 작업 트리와 전체 diff를 확인한다.
- 변경사항을 목적별 커밋 단위로 분류한다.
- 커밋 대상 파일만 stage한다.
- staged diff가 요청 범위와 일치하는지 확인한다.
- staged diff에서 비밀 정보와 불필요한 산출물을 확인한다.
- 커밋 메시지를 staged diff에 맞게 작성한다.
- 커밋 후 커밋 내용과 남은 변경을 확인한다.

## 커밋 메시지

형식은 다음과 같다.

```text
{type}: {한글로 작성한 변경 설명}
```

허용하는 `type`은 `feat`, `chore`, `refactor`, `fix`, `test`다.

커밋 설명은 staged diff의 실제 변경 목적을 구체적으로 표현한다.

## Output Contract

- 커밋 ID와 커밋 메시지
- 커밋된 파일과 변경 목적
- 커밋 전후의 작업 트리 상태
- 실행한 검증과 결과
- 남은 변경과 미해결 사항

## Verification Gate

- [ ] 저장소와 현재 브랜치를 확인했는가?
- [ ] 전체 diff를 읽고 커밋 범위를 분류했는가?
- [ ] staged diff가 사용자 요청 범위와 일치하는가?
- [ ] staged diff에 비밀 정보와 불필요한 산출물이 없는가?
- [ ] 필요한 테스트와 검증 결과를 확인했는가?
- [ ] 커밋 메시지가 staged diff의 목적과 일치하는가?
- [ ] 커밋 후 커밋 내용과 남은 변경을 확인했는가?

하나라도 확인하지 못하면 커밋을 완료로 보고하지 않는다.

## Failure Policy

- 저장소나 브랜치를 확인하지 못하면 커밋하지 않는다.
- 전체 diff를 읽지 못하면 커밋하지 않는다.
- 커밋 범위가 불명확하면 사용자에게 확인한다.
- staged diff가 요청 범위와 다르면 stage를 수정하거나 사용자에게 확인한다.
- 필수 검증이 실패하면 원인과 미커밋 상태를 보고한다.
- 비밀 정보나 범위 밖 변경이 발견되면 커밋을 중단한다.
- 커밋 결과 확인에 실패하면 성공으로 보고하지 않는다.

## Exit Criteria

- 완료: 검증된 범위만 커밋하고 결과를 전달했다.
- 대기: 사용자 결정이나 추가 검증이 필요하다.
- 실패: 커밋 또는 필수 검증을 완료할 수 없다.
- 취소: 사용자가 커밋을 취소했다.
