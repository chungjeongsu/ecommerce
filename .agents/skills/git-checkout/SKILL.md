# Git Checkout

## Boundary

### Always

- 현재 저장소와 브랜치를 확인한다.
- 작업 트리와 미커밋 변경을 확인한다.
- 자연어 요청에서 버전, 작업 식별명과 상세 작업명을 추출한다.
- 완성된 브랜치명 후보를 사용자에게 확인한다.
- `main`과 `origin/main`의 동기화 상태를 확인한다.
- 전환 후 브랜치와 기준 커밋을 다시 확인한다.

### Ask First

- 브랜치명 구성 요소를 자연어에서 식별할 수 없는 경우 확인한다.
- 작업 트리가 깨끗하지 않은 경우 처리 방법을 확인한다.
- 로컬 브랜치와 원격 브랜치가 충돌하는 경우 확인한다.
- 기존 브랜치의 목적이나 기준 브랜치가 불명확한 경우 확인한다.

### Never

- 사용자 확인 없이 브랜치명을 정하지 않는다.
- 이미 존재하는 작업 브랜치로 자동 전환하지 않는다.
- 미커밋 변경을 폐기하지 않는다.
- `reset --hard`나 강제 checkout을 수행하지 않는다.
- `main` 동기화 실패 후 작업 브랜치를 생성하거나 전환하지 않는다.

## Input Contract

- 자연어 요청 또는 버전, 작업 식별명과 상세 작업명
- 기준 원격과 기준 브랜치
- 현재 작업 트리의 보존 방법
- 사용자 확인이 필요한 미해결 사항

브랜치명이나 미커밋 변경 처리 방법이 없으면 전환하지 않고 확인한다.

## Responsibilities

- 작업 식별명을 `feat`, `fix`, `refactor`, `test`, `chore` 중 하나로 분류한다.
- 상세 작업명을 영문 소문자 kebab-case로 변환한다.
- 작업 브랜치명을 `{버전}/{작업식별명}/{상세 브랜치명}`으로 구성한다.
- 완성된 브랜치명 후보를 사용자에게 확인한다.
- 현재 브랜치, 작업 트리와 사용자 변경을 확인한다.
- 변경이 있으면 commit, stash, 중단 또는 폐기 중 처리 방법을 확인한다.
- 폐기를 선택하면 데이터 손실 가능성을 다시 확인한다.
- `main`으로 전환하고 `git pull origin main`을 실행한다.
- 지정한 브랜치가 없으면 동기화된 `main`에서 생성한다.
- 지정한 브랜치가 있으면 중단하고 새 브랜치명을 확인한다.
- 전환 후 브랜치, 기준 커밋과 보존된 변경을 확인한다.

## Output Contract

- 최종 브랜치명
- 기준 브랜치와 기준 커밋
- 전환 전후 작업 트리 상태
- 보존된 사용자 변경
- 실행한 동기화 결과
- 미해결 사항

## Verification Gate

- [ ] 사용자 확인을 받은 브랜치명을 사용했는가?
- [ ] 상세 브랜치명이 영문 소문자 kebab-case인가?
- [ ] 전환 전 작업 트리와 미커밋 변경을 확인했는가?
- [ ] `main`이 `origin/main`과 동기화되었는가?
- [ ] 기존 사용자 변경이 보존되었는가?
- [ ] 최종 브랜치와 기준 커밋을 확인했는가?

하나라도 확인하지 못하면 브랜치 전환을 완료로 보고하지 않는다.

## Failure Policy

- 작업 트리가 깨끗하지 않으면 처리 방법 확인 전까지 전환하지 않는다.
- 기존 브랜치가 있으면 새 브랜치명 확인 전까지 전환하지 않는다.
- `main` 동기화가 실패하면 작업 브랜치 작업을 중단한다.
- 브랜치 충돌이 발생하면 사용자 결정 전까지 대기한다.
- 기존 변경 보존 여부를 확인하지 못하면 성공으로 보고하지 않는다.
- 파괴적 복구가 필요하면 사용자 승인 전까지 수행하지 않는다.

## Exit Criteria

- 완료: 확인된 브랜치로 전환하고 기준 상태를 전달했다.
- 대기: 사용자 결정이나 추가 권한이 필요하다.
- 실패: 동기화, 전환 또는 필수 검증을 완료할 수 없다.
- 취소: 사용자가 브랜치 전환을 취소했다.
