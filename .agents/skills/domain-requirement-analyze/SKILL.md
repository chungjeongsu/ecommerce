# Domain Requirement Analyze

## Boundary

### Always

- 사용자 요구사항 원문을 보존한다.
- `.agents/domain/` 후보 문서의 frontmatter를 먼저 읽는다.
- 사용자 요구사항과 관련된 도메인 문서 본문을 끝까지 읽는다.
- 읽은 문서 경로와 적용한 규칙을 기록한다.
- 문서의 사실과 분석 판단을 구분한다.
- 누락, 모호, 미결정과 충돌을 구분한다.
- 각 판단을 근거 문서와 연결한다.

### Ask First

- 분석 대상 도메인을 식별할 수 없는 경우
- 요구사항의 의미에 따라 적용 규칙이 달라지는 경우
- 사용자 요구사항과 기준 문서가 충돌하는 경우
- 도메인 규칙이나 생명주기 변경이 필요한 경우
- 여러 도메인 중 규칙 소유자를 결정할 수 없는 경우

### Never

- 문서에 없는 규칙을 확정된 규칙으로 간주하지 않는다.
- 모호한 요구사항을 임의로 확정하지 않는다.
- 사용자 답변 없이 도메인 문서를 변경하지 않는다.
- 코드, 테스트와 마이그레이션을 생성하거나 수정하지 않는다.
- 패키지, 클래스와 기술 구현 방법을 결정하지 않는다.

## Input Contract

- 분석할 사용자 요구사항 원문
- 사용자가 확정한 범위와 결정
- 분석 대상 도메인을 식별할 수 있는 정보

요구사항 원문과 사용자 결정을 구분할 수 있어야 한다.

## Responsibilities

- 관련 도메인과 후보 문서를 식별한다.
- 관련 문서의 객체, 행위, 속성, 불변식, 관계와 생명주기를 확인한다.
- 사용자 요구사항에 적용되는 기존 규칙을 식별한다.
- 요구사항에서 새로 결정해야 하는 도메인 규칙을 식별한다.
- 기존 규칙 유지와 규칙 변경을 구분한다.
- 질문이 필요한 항목을 선행 결정 순서로 정리한다.
- 확정 규칙과 미확정 규칙을 분리한다.

## Output Contract

- 사용자 요구사항 원문과 분석 범위
- 읽은 도메인 문서 경로
- 적용되는 기존 도메인 규칙과 근거
- 새로 확정된 도메인 규칙과 사용자 결정
- 관련 객체, 행위, 속성, 불변식, 관계와 생명주기
- 누락, 모호, 미결정과 충돌 항목
- 기존 규칙 유지 또는 규칙 변경 필요 여부
- 분석 완료 상태

## Verification Gate

- [ ] 관련 도메인 후보의 frontmatter를 확인했는가?
- [ ] 선택한 도메인 문서 본문을 끝까지 읽었는가?
- [ ] 읽은 문서와 적용 규칙을 기록했는가?
- [ ] 모든 판단을 근거 문서나 사용자 결정에 연결했는가?
- [ ] 누락, 모호, 미결정과 충돌을 구분했는가?
- [ ] 기존 규칙 유지와 규칙 변경을 구분했는가?
- [ ] 코드 구조와 구현 방법을 결정하지 않았는가?

하나라도 확인하지 못하면 분석 완료로 처리하지 않는다.

## Failure Policy

- 필수 문서를 읽지 못하면 누락 경로를 보고하고 중단한다.
- 분석 범위가 불명확하면 사용자에게 질문하고 대기한다.
- 문서 간 충돌은 임의로 해결하지 않는다.
- 사용자 결정이 필요한 규칙은 확정 상태로 출력하지 않는다.
- 모든 판단의 근거를 연결하지 못하면 완료로 보고하지 않는다.

## Exit Criteria

- 완료: 도메인 요구사항과 규칙 상태를 근거와 함께 전달했다.
- 대기: 사용자 결정이나 추가 도메인 정보가 필요하다.
- 실패: 문서 로딩이나 필수 분석을 완료할 수 없다.
- 취소: 사용자가 분석을 취소했다.
