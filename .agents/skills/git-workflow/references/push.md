# Push 컨벤션

## Push 전 확인

- 현재 브랜치와 대상 원격 브랜치를 확인한다.
- 현재 작업 브랜치의 기준 브랜치와 merge-base를 확인한다.
- 작업 트리에 커밋되지 않은 변경이 남아 있는지 확인한다.
- 요청한 모든 변경사항이 커밋에 반영되었는지 확인한다.
- 기준 브랜치부터 현재 HEAD까지의 전체 커밋, 파일과 내용을 실제 diff 기준으로 읽는다.
- 필요한 테스트, 빌드, 정적 검증과 리뷰 결과를 확인한다.
- push하지 않은 로컬 커밋과 원격 브랜치의 차이를 확인한다.
- 비밀 정보, 불필요한 산출물과 요청 범위 밖의 변경이 없는지 확인한다.

확인되지 않은 변경이나 필수 검증 누락이 있으면 push하지 않는다.

## 보고 범위

Push 보고는 마지막 커밋이나 직전 push 이후의 증분만 설명하지 않는다.

- 기본 기준은 `origin/main...HEAD`의 전체 diff와 `origin/main..HEAD`의 전체 커밋이다.
- 다른 기준 브랜치에서 시작한 작업이면 실제 merge-base가 있는 원격 기준 브랜치를 사용한다.
- 동일 브랜치를 여러 번 push하더라도 보고에는 기준 브랜치부터 현재 HEAD까지의 전체 작업 내용을 포함한다.
- 이전 push 이후 새로 추가된 내용은 전체 변경 안에서 별도로 구분할 수 있다.
- 기준 브랜치, 대상 브랜치, 전체 커밋 목록과 전체 변경 파일을 실제 Git 결과로 확인한다.

## Push 보고

push 전 다음 형식의 한국어 Markdown 보고를 구성한다. Push가 이미 승인된 경우 원격 반영 결과까지 포함해 최종 Output으로 전달한다.

```markdown
# Push 보고

## 대상

- 기준 브랜치: {원격 기준 브랜치}
- 대상 브랜치: {현재 작업 브랜치와 원격 브랜치}

## 전체 커밋

- {기준 브랜치 이후 전체 커밋}

## 수정/추가사항

### 코드

- {수정하거나 추가한 코드와 목적}

### 테스트

- {수정하거나 추가한 테스트와 검증 대상}

### 문서·설정

- {수정하거나 추가한 문서·설정과 반영 내용}

### Skill·Workflow

- {추가하거나 변경한 Skill·Workflow와 책임}

### 기타

- {그 밖의 변경사항}

## 전체 변경 파일

- {기준 브랜치 이후 수정·추가·삭제된 전체 파일}

## 검증

- 작업 트리 상태: {clean 또는 남은 변경}
- 커밋 반영 상태: {모든 변경 반영 여부와 확인 방법}
- 테스트: {실행한 테스트와 결과, 없으면 사유}
- 빌드·정적 분석: {실행 결과, 없으면 사유}
- 리뷰: {검토 내용과 결과}
- 문서·규칙: {확인한 문서와 일관성 결과}
- 보안·범위: {민감 정보와 범위 밖 변경 확인 결과}

## 미해결 사항

- {없으면 `없음`}
```

보고에는 실제 변경된 내용과 추가된 내용을 구분해 기록하고, 코드·테스트·문서·설정·Skill·Workflow 변경을 빠짐없이 포함한다.
검증에는 작업 트리, 커밋 반영 여부, 테스트, 빌드·정적 분석, 리뷰, 문서 일관성, 보안·범위 확인 결과를 포함한다.
해당하지 않는 항목도 생략하지 않고 `해당 없음`과 사유를 기록한다.

## 실행 기준

1. Push 전 상태와 변경 누락 여부를 확인한다.
2. 기준 브랜치부터 현재 HEAD까지의 전체 변경사항과 검증 결과를 읽고 한국어 Markdown 보고를 작성한다.
3. 현재 사용자 요청이나 이전 결정에 push 승인이 포함되어 있는지 확인한다.
4. 이미 승인된 push라면 동의를 다시 요청하지 않고 승인된 원격에 push한다.
5. push 승인이 없다면 보고 내용을 전달하고 승인을 기다린다.
6. push 결과와 로컬·원격 HEAD 일치 여부를 다시 확인한다.
7. 최종 Output에는 전체 Push 보고와 실제 원격 반영 결과를 함께 전달한다.

원격 저장소 변경이나 강제 push는 별도 승인이 없으면 수행하지 않는다.
