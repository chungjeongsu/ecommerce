# Checkout 컨벤션

## 브랜치명 확인

작업 브랜치를 준비하기 전에 사용자에게 다음 세 값을 질문한다.

- 버전
- 작업 식별명
- 상세 브랜치명

브랜치명은 다음 형식으로 구성한다.

```text
{버전}/{작업식별명}/{상세 브랜치명}
```

예시:

```text
v1/fix/inventory-status-guard
```

사용자 확인 없이 버전, 작업 식별명 또는 상세 브랜치명을 임의로 정하지 않는다.

## 전환 순서

브랜치 전환은 반드시 다음 순서로 수행한다.

1. 현재 브랜치와 작업 트리 상태를 확인한다.
2. 사용자 변경과 미커밋 변경이 있는지 확인한다.
3. `main` 브랜치로 전환한다.
4. `git pull origin main`을 실행한다.
5. 지정한 작업 브랜치가 없으면 `main`에서 생성한다.
6. 지정한 작업 브랜치가 있으면 해당 브랜치로 전환한다.
7. 최종 브랜치와 기준 커밋을 확인한다.

## 안전 규칙

- 미커밋 변경을 폐기하지 않는다.
- 작업 트리가 깨끗하지 않으면 stash, commit, 유지 중 처리 방법을 사용자에게 질문한다.
- `reset --hard`, 강제 checkout과 같은 파괴적 전환은 수행하지 않는다.
- `main` 동기화가 실패하면 작업 브랜치를 만들거나 전환하지 않는다.
- 원격 브랜치와 로컬 브랜치가 충돌하면 사용자 결정 전까지 대기한다.

## 완료 조건

- 사용자에게 확인한 형식의 작업 브랜치가 준비되었다.
- `main`이 `origin/main`과 동기화되었다.
- 기존 사용자 변경이 보존되었다.
- 현재 브랜치와 기준 커밋을 다음 노드에 전달했다.
